# 工作流能力增强（2026-09-09）

## 生效范围

所有难度全局生效：逐步骤证据校验、混合错误分类与正确性优先、失败尝试记忆、连续不改善后的有界概率建模重检。保留原有模型、高推理强度和 token 上限。

只有公开样例/小规模穷举前置验证按难度启用：洛谷“省选/NOI−”及以上（省选/NOI−、NOI/NOI+/CTS）。提高、提高+/省选−及更低难度不触发；难度未知时也不自动触发。该设置不影响全局能力。

## 难题前置验证

1. 从原始题面提取明确成对的公开输入/输出代码块，支持 input/output 标签及中英文样例标题，最多 4 对。无法明确提取时记录 UNAVAILABLE，不虚构样例答案。
2. 在已有 Docker 隔离环境编译并执行公开样例。失败时暂缓本轮昂贵模型评审，把公开反例交给修复器；仍保留正式判题结果。编译结果供正式评测复用。
3. 样例通过后，独立模型调用只接收题面，生成小规模穷举程序及最多 6 个微型输入，说明枚举空间。它不接收候选代码或私有测试。
4. 穷举程序先通过公开样例校验，才用其输出与候选程序进行差分比较。每个执行限时不超过 2 秒，并受原题内存限制和 16 KiB 输出上限约束。程序仅在 Docker 中执行，不在宿主直接运行。
5. 生成程序不是形式证明；差分不一致作为需调查的证据，修复器必须同时核查候选与穷举器。程序完整性、编译或样例校验失败会反馈给模型，最多尝试 3 个程序候选；耗尽后明确降级，不能宣称穷举通过。基础设施失败与已耗尽的模型请求不额外重复生成。

编译、公开用例结果和穷举计划逐项保存在检查点；同一源码的已完成验证及同一运行的穷举器可复用。`public_validation/*.json` 与 `public_cases/` 保存公开证据，完全独立于私有测试集。图形补充不会被当作额外样例来源。

## 全局逐步骤评审

模型请求使用严格的动态评审 schema：assessments 长度必须等于解法步骤数，逐项覆盖且不能重复，evidence 不得为空或空白；错误分类、首错步骤、代码位置需一致，角色必须正确。算法评审、代码评审和证据复核均适用。

校验失败进入现有有界重试，要求完整重生成评审；不降低推理预算，不把空数组填充成通过。重试耗尽明确报错，不能当作有效诊断继续修复。旧检查点中不合格的未完成评审会重新获取；已经结束的历史运行保持原样。模型评审因公开失败暂缓时只记录 NOT_ASSESSABLE，不伪造模型意见。

## 全局修复策略

分别统计 RE、WA、IO_CONFLICT、OLE、MLE、TLE，依次处理可执行性/正确性、内存和时间。聚合判题 verdict 仍保留原义；混合 TLE+WA 时修复建议先解决错误答案，不再只优化耗时。正式私有输入和答案仍不发给模型。

每轮持久化修改差异摘要、分类计数、公开反例和是否改善。下一轮携带最近最多 3 轮中未改善的尝试（差异摘要每轮最多 5000 字符）。源码不变但证明变化时保存独立推理版本并重新评审，复用编译和判题结果；只有源码和推理均不变时才记录为无修改。best 版本保留为安全基线，同时让模型知道之前哪些改法已经失败。公开反例最多选 2 个并按字段限长，完整内容仍存本地。

连续不改善达到现有阈值时进行一次概率判断。默认概率 0.5，最多重检 1 次；只有剩余修复轮数足够才触发，不增加用户设置的修复总轮数。决策由运行 ID 与轮次稳定派生并写入检查点，因此重启不会重新抽取。重检调用不携带旧完整代码，要求从题意重新推导、检验充分性并改变失败路线；失败记忆与公开反例仍保留。

在 `configs/app.toml` 的 `[repair]` 配置：

```toml
public_preflight_enabled = true
rethink_probability = 0.5
max_rethinks = 1
```

概率 0 禁用重检，1 表示满足阈值和预算时必定触发。WebUI 显示前置验证、评审暂缓和重检决策；嵌套模型进度显示独立穷举器及建模重检。

## 验证边界

287 项 Python 测试及 28 项前端测试通过。离线测试覆盖严格评审重试、混合错误、简单/困难题的完整修复循环、失败记忆、概率边界/次数/恢复、公开样例提取、短路、穷举器校验和差分反例。另通过真实 Docker 编译及 AC/WA 用例验证新增执行器，未提供私有数据集对象。

本次没有调用付费模型，也没有重跑历史评测。测试证明新增控制流程和隔离执行可用，不能据此量化实际难题通过率的提升。穷举器质量依赖模型；样例较大、无法提取或穷举超时的题目会明确降级，不会伪报验证通过。
