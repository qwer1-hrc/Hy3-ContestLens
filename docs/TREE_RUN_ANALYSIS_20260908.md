## 独立复现与明确缺陷

读取原始三份 C++，不改源代码，在临时目录用本机 g++ -O2 -std=c++17 编译，运行公开样例和两节点例子。结果记录在 `G:/hy3/tmp/tree-run-analysis/results.json`；这些是离线分析材料，没有改动运行产物。

两节点输入：

```text
1
2
1 2
1 2
```

唯一操作是交换两个数字，所以正确输出 `2 1`；三版分别输出 `0 0`、`2 0`、`0 0`。

**共同缺陷：路径构造漏掉最近公共祖先。** 公共前缀长度为 i/l 后，两段拼接均从该下标开始，遗漏下标 i-1/l-1 的 LCA。路径 1→2 被构造成 `[2]`；兄弟节点间路径也丢掉连接它们的父节点，后续把非边当边或把真实路径当作零长度。这不是提高推理预算就能解决的执行反馈缺失。

**r002 的切边等式同时混用了候选加入前后的状态。** `rem_start/rem_end` 已扣除候选，但 `cross` 没有加上候选路径。第一项尚无已提交状态时，等式要求起点与终点在每一条切边的同侧，等价于同一个节点；代码却禁止终点等于起点。因此候选被拒绝，P 保持为零。真实小测试输出也全部为零。

**复杂度没有达标。** 外层数字 × 候选点 × 遍历树边，至少有 O(n³) 的结构风险；r000/r002 内再遍历路径或按父指针查询子树，最坏还有一层 n，部分逻辑可能达到 O(n⁴)。这里给的是循环上界分析，实际耗时受提前拒绝影响；实际大测试 TLE 已被判题确认。

公开样例第一组正确结果为 `1 3 4 2 5`，三版分别输出 `1 2 0 0 0`、`1 2 4 0 0`、`0 0 0 0 0`。另独立枚举该组 4 条边的全部 24 种删边顺序，最优确为 `1 3 4 2 5`，没有任何合法结果以 `1 2` 开头。当前所谓“可行性检查”至少在实现上会接受无法完成的前缀，不能仅靠模型声称贪心正确。

## 工作流为何未纠正

1. 没有独立的公开样例/小规模差分验收步骤。样例存在于上下文，不等于被执行并产生可交给修复器的反例。
2. 本次全部评审及复核的 assessments 为空，error_type=UNRESOLVED、first_error_step_id/code_location=null。摘要虽然声称发现缺陷，却没有形成有效结构化定位。质量问题有记录但不会触发算法评审重做；代码复核之后仍可能保持同样无效形态。
3. 算法评审反复将“n=1 不处理”列为缺陷，而三版代码均有 n==1 分支；它隔离于源码，不能凭摘要断言实现缺失。代码评审未指出共同的 LCA 遗漏，显示双路角色隔离并不等于真正独立且经过验证的推导。
4. TLE 汇总及固定修复建议引导先查终止/性能；WA 证据虽存在，却没有形成“先修复两节点与公开样例”的可执行门槛。
5. 两次修复均以 r000 为 best 基线。保留最好版本是合理的，但下一次请求只收到 best_solution、best diagnosis、best judge 和轮次，没有上一失败候选及已证伪修复假设，容易重复探索。
6. 修复质量门禁 `passed=true` 不代表提高分数；记录同时显示 fixed_tests=[]、candidate_rank_improved=false、评审结构缺失。没有回归时，零分变零分仍可能通过该门禁。

## 保持模型不变时的改进优先级（仅建议）

1. **先执行公开样例与微型穷举差分，再做昂贵盲审。** 本题可对 n≤7 枚举所有 (n-1)! 删边顺序，生成可信最优答案；自动缩小反例。算法需要保持模型和原有 high 推理强度不变，只增加外部验证反馈。
2. **结构化评审完整性必须通过。** 逐步骤覆盖、矛盾类型、首错步骤和代码位置互相一致；摘要“说发现了错误”不能代替 assessments。无效评审应修复评审，避免把无效诊断直接转成改代码任务。
3. **WA 与 TLE 分开处理。** 先要求小例子正确、输出为 1..n 的排列、路径端点正确且相邻节点确有边，再核查 n=2000 的复杂度。公开/合成反例可以给模型；私有测试继续隔离，不必泄露隐藏答案。
4. **保留失败记忆。** best 代码继续作为可回退版本，同时另传上轮尝试、反例、否定的假设和不应重复的改法。连续不改善应重建模型或换路线，而不是只在同一未经证明的约束集合上补丁。
5. **把可行性证明做成明确前置任务。** 贪心必须证明判定条件充分且可延拓；先用小规模 oracle 推翻错误命题。可在固定总预算内采用不同建模候选，用可执行证据筛选，优于重复三次同一路径；但不能保证同一模型一定能解出所有难题。
