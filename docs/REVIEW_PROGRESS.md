## 重复生成防护

算法评审、代码评审和证据复核使用正文重复检测；不检查推理内容，不用于求解器或修复器的源代码输出。维护最近 8192 字符，每新增至少 1024 字符检查一次。需要至少 40 个完整句子、句子覆盖至少 6000 字符、重复句占比至少 85%、不同句子占比至多 25%，才终止当前流并记录 `repetitive_output`。

终止后使用已有的有界重试流程，反馈仅含失败类型，不把异常输出重新加入提示词；必须重新收到完整响应并通过结构校验后才接受结果。没有降低推理强度或缩减正确性检查。评审提示额外要求避免重复说明、输出完整 JSON 后结束。非流式返回也检查重复，但无法节省已经生成的部分。

该规则刻意保守，不能识别所有重复模式。误报仍存在理论可能，不能用一次题目测试证明所有题目效果不变。

## WebUI

层级为：现有大步骤 → 模型调用 → 第几次尝试 → 等待、推理、生成、校验、重试或结束。

- `MODEL_CALL_PROGRESS` 事件通过 `parent_seq` 归属原大步骤，以 `call_id` 区分并行调用，以 `attempt` 保留重试历史。
- 状态变化立即记录；接收流时同状态进度最多每 5 秒记录一次，界面每秒刷新耗时。
- 事件不包含提示词、源代码、推理文本或密钥；仅包含状态、正文字符数、时间、角色和失败类型。
- 手动折叠不会被后续流更新强制展开；支持全部展开/折叠。
- 运行项显示呼吸点和旋转指示器；结束、取消、断开连接时停止运行指示；支持减少动态效果设置。
- 历史无进度事件的评测继续使用原来的大步骤展示，不伪造历史细分进度。
